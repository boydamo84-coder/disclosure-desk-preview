## Inventory and release rule

Current directory dataset: **50 people**, **20 sourced portrait links**, **30 initial-only tiles**. All 50 biographies retain `research-copy-edit-needed`. Their proposed timelines, videos, coverage, podcasts, social handles, documents, claimed affiliations, dates and case connections require human fact-checking. Source and licence labels in repository JSON are *claims to verify*, not proof of legal clearance. Do not mark profiles verified because tests pass or a URL resolves.

The R2 website renderer displays credited image URLs directly from Wikimedia Commons if the browser can load them; no image bytes are bundled. A preview may show initials when images are blocked. Photo entries now display visible credit, a source-page link, the exact declared Creative Commons licence deed when applicable, and a statement that the display is cropped to fit. Creative Commons attribution guidance: https://creativecommons.org/reusing-cc-licensed-content/

## Release acceptance workflow

1. **Editorial:** For every one of the 50 biographies, trace every potentially contentious statement and date to a primary or reputable publisher source; separate first-hand statements, second-hand claims, reporting, commentary and interpretations. Confirm current public roles/affiliations. Independently review the film/podcast/social entries rather than assuming a mention is an appearance.
2. **Visual and rights:** Inspect each of the 20 linked images, identity, original photograph, licence and any required rights/attribution on Samsung and desktop; confirm caption and source are accurate and sufficiently legible. Verify URL and portrait load; fall back to initials on failure.
3. **Source link integrity:** Test live HTTP destinations for original documents, links and podcast/video pages; valid HTTPS syntax is not live-link verification. Replace dead links with accurate originals or label them unavailable.
4. **Real-device journeys:** On Android Chrome and iPhone Safari preview, test Who's Who from all 14 navigation tabs, role/search filters, person deep links, profile → linked Archive/dossier → Back to source → directory card, external links, social chat and account privacy.
5. **Production gate:** Complete content/rights sign-off and exact final code/PR automated QA, then promote draft PR #12; merge only after a stable R1 smoke and owner acceptance, publish once, confirm new Netlify Published revision and real live routes. Preserve R1 rollback SHA `5f602cdcd832e84a6fee49bd1f7c29b1b7e99b21`.

**Nothing in this ledger constitutes publication approval.** No Supabase/Auth, AdSense, Play Store or live data action is required by this checklist.
