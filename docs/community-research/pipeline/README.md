# Offline scan → render → quota integration QA (no deploy)

This is an acceptance test for independently implemented workers, NOT a production orchestration layer, upload/publish transport, delivery or storage service. No service credentials, live accounts, user PDFs, live schema, public routes, or storage operations. It cannot be integrated into live requests: the runner imports the fixed synthetic fixture from scanner QA, and the two separate QA containers accept only that fixture, specific fictional refused variants or a deliberately altered copy. Worker container commands use local stdin/stdout without network, ports, host mounts or privileged access. The scanner uses its real offline ClamAV fixture signature and qpdf, and the renderer receives the exact resulting receipt from the local trusted test process; no official signature database is obtained. This is not proof of receipt authenticity outside local CI. Missing official signatures via the production scanner entry point must block. Test-only container commands are not part of either production image or public package.

Acceptance points:
- Real disposable PostgreSQL 17 ledger reserves exact fictional original bytes before scanning. Actual scanner output must bind source SHA-256, length, and page count. Only passed receipts enter the local test's renderer branch, then separate Poppler produces every PNG and manifest. Rehash actual encoded outputs and reserve each separately in one atomic ledger transaction. The `approved_copy` ledger kind is an intended representation reservation, NOT proof of approval/publication. No actual storage or published state.
- Real flagged test signature, active PDF content, invalid digest and missing official antivirus signatures cannot invoke the renderer in the test sequence. The original's accounted reservation persists during delete_pending. Only a simulated trusted deletion timestamp releases it; no Storage API is used.
- Actual renderer refuses source bytes altered after scan and a wrong scanned page count; no partial bytes or manifest.
- Artificial ledger padding leaves room for the first PNG alone, not the entire multi-file candidate. One transaction rolls back every attempted reservation if the full representation cannot fit. Actual objects are never persisted, including before reservation.

Future publication still requires a separately reviewed authenticated service/interface, trusted receipt provenance, live official signature and host capacity acceptance, private Storage reservation/immutable object verification/deletion/reconciliation, exact informed consent and representation review, approved public serving/download policy and accessibility, actual authorization/abuse checks, strict package acceptance and owner approval. This QA does not change or bypass the earlier rejected publication operation, W.NE export, production feature flags or allowlist. No new service or cost commitment.
