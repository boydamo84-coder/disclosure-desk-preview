# One-off official signature-set QA, no deploy

This test resolves a specific component-level uncertainty: does the existing unchanged `worker.inspect` code successfully use official-only ClamAV signatures, including its strict freshness check, and real qpdf on a fixed fictional clean PDF within the 4 GB CI container? The official ClamAV 1.5 image contains packaged databases; the build copies these into a separate QA-only scanner image (no daemon, updates, credentials, real documents, host mounts, live services or public routes). Log exact image digest, result, elapsed time and peak child process RSS. If the packaged signature set is stale, absent, incompatible, or the worker cannot perform a confirmed clean scan, fail closed; do not relax the official-only/freshness requirements or rerun downloads repeatedly. Official images can contain slightly stale signatures; see https://docs.clamav.net/manual/Installing/Docker.html (recommended 3–4 GiB, preloaded images and data use guidance). This workflow intentionally triggers only for this dedicated QA path; no schedule, production artifact or recurring download. The application must separately establish a persistent trusted FreshClam updater, verified signature freshness, patched images, bounded host capacity with headroom, no exposure of the ClamAV socket, private storage and approved request/publication path. The test is not a production host acceptance, malware-free guarantee or approval. No new paid service or live change.
